# Game Adapter Contract

Every game integrates with the SDK through a small adapter. The adapter keeps
game rules outside the covenant engine, while the SDK handles escrow, signing,
settlement, and proof generation.

## Required

```js
const adapter = {
  name: "my-game",

  toMatch(room, state) {
    return {
      id: room.id,
      roundId: state.roundId,
      game: "my-game",
      stakeKas: room.stake,
      players: room.players.map((player, index) => ({
        seat: index,
        role: player.role,
        address: player.address,
        publicKey: player.publicKey
      }))
    };
  }
};
```

## Recommended

```js
const adapter = {
  name: "my-game",
  createState(options) {},
  toMatch(room, state) {},
  applyMove(match, state, move) {},
  getWinnerAddress(match, state) {
    return state.winnerAddress;
  }
};
```

## Design Rule

Keep the game fast and interactive off-chain. Put the money path on-chain:

1. Convert room state into a deterministic `match`.
2. Lock both players' stakes into a covenant escrow.
3. Let the game adapter validate moves and choose a winner.
4. Ask the SDK to settle the covenant to the winner's release path.
5. Show the proof generated by `ProofBuilder`.

## Match Fields

- `id`: stable match or room id.
- `roundId`: stable round id; change it when a rematch starts.
- `game`: adapter name.
- `stakeKas`: each player's stake.
- `players`: two players for the current engine.
- `claimPaths`: optional human-readable claim paths for proof output.
